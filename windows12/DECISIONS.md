# Decisions
D001: Use existing public avision1/AI-use. Exactly one matching installed repository. Do not create a replacement. Use sole checkout under supplied workspace cwd; only windows12 content materialized, shared Git metadata excepted.
D002 (provisional): Investigate Debian 13 amd64 KDE live image derivative first. Debian documents supported live desktops and Calamares installation. Alternatives: Ubuntu/Kubuntu LTS (different release/branding and packaging tradeoffs), Fedora KDE (faster release cadence), immutable systems (more integration complexity). Reusing a signed stable live installer avoids inventing partitioning/bootloader code. Final selection depends on contained build feasibility.
D003: Microsoft Office web integration is partial Office functionality, never native desktop Office parity. Account/network requirements and advanced-feature limits must be shown. Keep LibreOffice as an offline alternative where base image supplies it. Do not include Microsoft binaries, credentials or copyrighted branding assets.
D004: No isolation bypass. Namespace mechanisms are unavailable here; investigate full userspace virtualization or other genuinely contained approach. Never fall back to host chroot/package installation.
D005: First architecture amd64 is reversible and does not imply ARM support. Project working title Windows12 is user terminology; distributed UI must clearly identify independent Linux software, unaffiliated with Microsoft.
D006: User explicitly requires frequent pushes directly to main, contained in windows12. Authenticated GitHub tree/commit/ref tools are the publishing fallback because native git push lacks credentials. Preserve remote base tree, reject unrelated staged paths, fast-forward only. Reconcile sole local main to published equivalent commit after fetch; never force-push.
D007: Build direction is full QEMU TCG VM with project-contained disk and controlled project share. This avoids unsupported host namespaces; host tools are extracted locally rather than installed. Still under feasibility test.
D008: Use source-built live-build inside contained VM instead of remastering upstream ISO. Desktop overlay is a versioned .deb installed via packages.chroot, avoiding unmanaged payload ownership. Unit tests, deterministic double packaging and Debian package inspection precede the full ISO build. Until executed these are implementation, not validation results.
D009: Build-tool metadata authenticates Ubuntu signatures through the host archive keyring and hashes package indexes/payloads. Builder cloud image currently uses official HTTPS SHA512SUMS rather than detached signature verification; explicitly weaker assurance and a release hardening task. Full ISO is not bit-reproducible until guest repository snapshots/tool versions are pinned.
D010: TCG execution diagnosis: default emulated SMM froze in BIOS f000:ff53; smm=off allowed actual Debian kernel/userspace boot. Record this host-specific requirement, not universal guest support.
D011: Debian genericcloud kernel lacks9p. Remove all guest host-filesystem shares; export via a local HTTP PUT endpoint with exact filename allowlist, length/free-space limits, escape/symlink rejection and atomic .part rename. All guest writable storage is project-contained qcow2; all accepted host uploads are project artifacts. Guest streams outputs and exports exit marker last; host verifies nonempty ISO plus SHA256 before reporting build success.
D012: Managed HTTPS proxy requires its public environment CA in the builder guest. Inject CODEX_PROXY_CERT and run update-ca-certificates there; never disable TLS validation, commit environment certs, or ship transient builder trust in the target OS. Actual package-index HTTPS succeeded after this fix.
D013: Pin cloud build20261021-2638 using dated URL and enforced SHA512 image + SHA256 manifest lock; digest equals already validated cached image. This removes latest-pointer ambiguity but is still HTTPS-authenticated, not detached-signature verified. Target package snapshot pinning remains pending.
D014: First frozen-source resume attempt did not conclusively execute the recipe after reboot; stopped and preserved it. Fresh build is proven through package-index retrieval. Resume lifecycle requires further work before being advertised as reliable.
D015: Increase fresh builder virtual root from20GiB to24GiB and disable live-build caches to reduce risk from simultaneous expanded KDE filesystem, downloaded packages, squashfs and ISO. Host initial free space~29GiB; exported ISO needs additional space outside sparse VM disk. No active disk resize; preserved prior builder state before fresh start.
D016: Recursive generated synchronization copies of the active VM disk consumed~10.46GiB. Narrow audited cleanup removed42 stale regular files (age>120s, unchanged restat, protected real-disk/backing inodes); newest copies/configured disks/logs untouched. Avoid parallel/rapid filesystem tool invocations; use persistent monitor and its cleanup command. Synchronization mechanism remains an inference; no claim of platform repair. If this cannot remain bounded, stop with an explicit environment blocker rather than risk real state.
D017: Unattended monitor auto-runs the same reviewed cleanup every60s and requests QMP stop-only pause below6GiB after cleanup; never auto-resume or quit. Owner/session and pause marker recorded. Logging failure must not prevent pause; state persistence failures warn stdout, actual QMP state authoritative. Automatic cleanup/status verified, pause/resume and ENOSPC path not runtime-tested. This protects a running job if agent usage stops, without promising hosted-process survival after environment teardown.
