# Retained package download planning

`build/export-package-plan.py` runs only as root inside the contained builder VM with `/run/windows12-build-vm`. The controller must first establish that the previous VM/build stopped, boot the retained disk in inspection mode, and supply a new random 32-character lowercase hexadecimal nonce. The helper never starts a VM, clears a live-build lock, changes stage flags, updates indexes, downloads archives, or installs/configures packages. Do not execute this helper on the host.

Inside that already contained guest:

```
python3 -B /root/windows12-checks/build/export-package-plan.py --nonce NEW_RANDOM_32_HEX_NONCE
```

Success exclusively creates `/project-output/package-download-plan.json`, capped at 2 MiB. An existing plan or catalog-audit output causes refusal, so a controller must preserve/export previous evidence and explicitly select an output lifecycle before another run. An exclusive `/project-output/package-plan-NONCE` directory consumes each nonce and retains bounded command evidence. No prior evidence is removed. Failure emits `Package plan refused: ...`; it does not export a usable partial plan. The controller must enforce its own fresh boot/nonce association and accept only the expected nonce.

## Trust and selection

Only the builder's trusted `/usr/bin/apt-get`, `/usr/lib/apt/apt-helper` and installed `/usr/bin/gpgv` or `/usr/bin/sqv` run. The real Debian archive keyring `.pgp` is preferred; a regular `.gpg` is a fallback, and aliases are refused. SQV releases verified cleartext with `--cleartext`; verifier/keyring bytes are hashed and rechecked. The target supplies data, not executables. Each retained remote `InRelease` must verify under the builder's Debian archive keyring; its date and any expiry are checked. Every retained remote Packages index must match the signed release's uncompressed SHA256 and size. Unsupported or uncovered remote catalogs cause refusal. Compression is decoded read-only through the trusted apt-helper, with 256 MiB output and 90-second limits per index. Signature commands are also bounded. Signature verification supports the installed builder gpgv or sqv and `.gpg` or `.pgp` archive keyrings.

APT receives explicit target root, status, list, extended-state and configuration paths. Its cache and archives paths point to a newly created empty nonce-scoped workspace directory. It never inspects or alters the retained target archive cache. This also avoids APT 3.0.3’s cache-hit size-only acceptance and cache size-mismatch deletion branches. Binary cache generation is disabled. Target APT configuration is loaded to retain resolver policy; executable pre/post hooks are cleared in the final configuration. Only `--print-uris --no-remove install` is called, with a 180-second limit and 2 MiB output limit. No `update`, simulation/install execution, or download subcommand is called. `Acquire::ForceHash=SHA256` is explicit: apt 3.0.3's source otherwise selects MD5 for backward-compatible `--print-uris`. The helper never converts MD5 into SHA256.

Every printed remote URI must match the SHA256, size, Filename, package and version in a verified target catalog. Only reviewed Debian archive hosts and pool paths are accepted. Local package inputs are separately recorded with their file SHA256 and `host_download: false`. Every printed `file:` URI must resolve within the retained target `/packages` repository and its actual bytes must match SHA256 and size of an exact config package input. `local_archives` records the APT cache filename, size, SHA256, config `source_path`, and retained `target_source_path`. These are excluded from host downloads. Target status/config/source/stage file hashes, signed catalog hashes, verification keyring, queue digest, command-output digest and digest coverage accompany the plan. The helper checks retained inputs again before export.

## Consumer contract and remaining gates

Schema 1 contains `nonce`, `planning_only: true`, and `packages`, each with `url`, `filename`, positive archive `size`, lowercase `sha256`, `package`, and `version`. `local_packages` and `local_archives` are never host download queues. `coverage` counts every matched remote URI. The empty isolated APT cache makes this a full selected-transaction archive plan, including remotely sourced packages whose archives already exist in the retained target cache. It is not an inventory of already installed packages. The importer must authenticate every selected existing archive against the manifest SHA256 and size; existing filename/size alone is insufficient.

A host consumer must validate the expected nonce/schema, cap file/package/download sizes, reject duplicate names and conflicting hashes, and preserve exact URI/transport authorization. Any HTTP-to-HTTPS normalization belongs to the reviewed consumer and must retain origin/path identity; it cannot bypass TLS or network approval. Prefetch in bounded authorized batches and verify every received archive's SHA256 and size. Transfer verified files into the contained guest only. The importer must verify SHA256 and size of every selected archive immediately before native target APT installs the transaction. Native APT 3.0.3 accepts existing cache hits by size without rehashing, so `--no-download install` alone does not authenticate cached archives. Host prefetch success is not package installation or ISO success.

Only AST parsing and read-only archive-source inspection were performed during source authoring. Actual guest execution and manifest coverage remain required before using this path.

## Diagnostic catalog audit

Before invoking APT, the exporter checks every retained remote release signature and every retained remote Packages index, continuing through index SHA256/size mismatches to collect all diagnostics. It exclusively creates `/project-output/package-catalog-audit.json`, capped at 2 MiB, with schema 1, the fresh `nonce`, and `audit_only: true`. `signature_verification_completed` is true only when every retained release verified and passed date/expiry checks. Partial signature failures remain explicitly incomplete; their diagnostic contents are not an authenticated usable package plan. `all_catalogs_match` additionally requires zero mismatches and errors.

Each mismatch includes expected signed and actual uncompressed SHA256/size, stored-file SHA256/size, the first 32 stored bytes as `header_prefix_hex64`, the signed InRelease evidence, and release index path. The audit also records all inspected signed catalogs, verifier/keyring evidence, and target configuration/status/source provenance. Any mismatch or error stops planning before APT and no usable package plan is emitted. Refusal text includes the expected and actual SHA256 and byte counts. The audit never authorizes ignoring, repairing, or replacing bad metadata; a controlled native signed metadata refresh is a separate controller workflow.
