|---|---|---|
| DA-01 / medium, conditional | Source-proven panel repair gap: `image/usr/share/plasma/shells/org.kde.plasma.desktop/contents/updates/windows12-layout.js`, the `if (!widgets.length)` branch | Tray, clock and Show Desktop are added only when the selected panel originally has zero widgets. This does **not** establish that Debian's fresh default panel is incomplete. Reproduce in a disposable fresh test profile with a partially populated panel, execute the script once, and inspect the result. If that input is supported, track each essential widget independently and append only missing widgets. Debian explicitly describes Discover as the application that notifies about and installs system updates [1]. System Settings may expose update configuration through `kde-config-updates`, so this is not evidence that settings lack every update control. Prefer precise guidance: System Settings for hardware/accessibility preferences, Discover for installing applications and applying updates. Verify the actual menu labels and flows before changing screenshots or instructions. |
| DA-03 / medium readiness gap | Unassured Flatpak GUI integration: `build/guest-build.sh`, generated package list | The recipe directly selects `flatpak` and `plasma-discover`, but not `plasma-discover-backend-flatpak`. The direct package list therefore does not guarantee Discover's Flatpak backend; it also does not prove absence from the eventual transitive package manifest. No Flatpak remote setup appears in the reviewed overlay/recipe. Inspect the real manifest and Discover Sources page. Certify Debian repository installation/update first. Only promise a Flatpak catalog after its backend, selected remote and install/update/uninstall behavior are deliberately configured and tested. This is not a request to add a new store or repository automatically. |
| DA-04 / low readiness limitation | Source-proven English-only project help/labels: `welcome.html` and `image/usr/share/applications/windows12-*.desktop` | The help declares `lang="en"` and contains English text; project entries supply only unlocalized `Name`/`Comment` values. This does not imply Debian/KDE applications lack localization. Disclose the preview's project-help language and test another selected locale before making broader localization claims. Do not advertise universal language coverage from an English smoke test. |

## Important unknowns, not diagnosed defects

- **Fresh-profile Plasma behavior.** The script uses API concepts documented by KDE: panels/widgets, `addWidget`, configuration groups, and wallpaper configuration [2][3]. Documentation is not proof that this update-script path runs at the intended moment in this exact Debian Plasma build. Boot a genuinely new live and installed profile; check script execution, widget order, launcher alignment, panel height, pins, wallpaper and double-click behavior. Log out/in and verify no duplicate panel and no loss of user changes. Check both the selected default session and any separately advertised session type. Wayland task grouping and Chromium `--class`/desktop-entry association need actual observation.
- **Authenticated Microsoft services.** The allowlisted Word/Excel/PowerPoint domains match Microsoft's documented web app homepages [4]. That verifies domain intent, not Linux browser functionality, account eligibility, authentication, downloads, file picking, accessibility or tenant policy. Keep “web / partial support” labels. User-assisted authenticated tests must avoid storing credentials or private documents in artifacts. The source's Firefox fallback deliberately opens a normal browser window, which the help already discloses.
- **Login, administration and installation.** The recipe selects SDDM and the desktop task, but neither a package list nor the overlay proves a visible login/session or working Polkit/sudo authorization after installation. Test the resulting account and graphical package-management flow. A D-I root/package proof does not certify Calamares or a usable desktop.
- **Networking and peripherals.** Selecting NetworkManager/Plasma networking, Bluetooth and printing packages is implementation intent. Ethernet in a VM cannot establish Wi-Fi, Bluetooth, printer, suspend, sound or GPU support on arbitrary hardware. Preserve the existing exact-device coverage limits.
- **Accessibility.** Debian's KDE desktop task recommends KDE accessibility packages and Orca [5], but recommendations alone do not prove the final manifest, enabled features, readable UI, screen-reader speech or keyboard reachability. A functional test remains necessary; do not replace that evidence with package presence.

## First-release acceptance gates

These expand the existing `docs/VALIDATION.md` into observable checks, without declaring them passed or adding product features.

| Gate | Minimum reproducible test and retained evidence |
|---|---|
| Live desktop and session | Boot the actual checksum-verified ISO; capture visible Plasma, panel/menu/tray/clock/wallpaper. Open apps, lock/unlock if supported, log out/in, restart and shut down using the visible controls. Record session type, image/package versions and screenshots. |
| Installed desktop and account | Install to a newly created contained disk, detach ISO, boot the disk, sign in as the created user, confirm correct home ownership and that live credentials/configuration did not unexpectedly migrate. Exercise an ordinary admin authorization prompt and reboot again. Test Calamares separately from D-I. |
| Files and common documents | In Dolphin create a folder/file; copy, move, rename, trash and restore it. Open/save a disposable text document, spreadsheet and presentation in LibreOffice, then close/reopen them. Test PDF, archive and download opening; record format caveats rather than claiming Office fidelity. |
| Web Office | Launch all curated entries as a regular user and verify official destination and sensible window/task grouping. With an eligible user-controlled account, create/edit/export disposable Word, Excel and PowerPoint files, exercise file picking/downloads, sign out, and test network loss/recovery. Record exact browser and service/account scope. |
| Network, software and updates | Connect the VM through its intended network UI, resolve and load an HTTPS site. In Discover install and remove a harmless repository application, apply an available update, authorize normally and reboot if required. Inspect repositories, signatures, failed package operations and known build proxy/CA leakage. Verify Flatpak only if it is intentionally offered. |
| Keyboard and display | Reach launcher, application switcher, settings and dialogs with the keyboard; check documented shortcuts, focus visibility, file selection and authorization dialogs. Exercise ordinary and high display scaling and a smaller display; check clipped labels and help readability. |
| Accessibility and locale | Test available large-text/scaling/contrast settings and keyboard-only use. If screen-reader support is advertised, prove speech/focus behavior in a representative desktop and browser flow. Test selected non-English locale separately and disclose untranslated project help. |

For every gate retain image SHA256, environment, exact steps, expected/actual result and artifacts inside the project. A failed gate should produce a specific fix and repeat test, not a relaxed success definition. Physical hardware remains separate, individually scoped evidence. No claim that “everyone” or every Windows application/device is supported follows from a VM release test.
