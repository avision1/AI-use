## Concrete boundedness issue

Before treating the exporter as fail-closed on arbitrary retained input types, change `regular()` to open with `O_NOFOLLOW | O_NONBLOCK` and validate the descriptor before reading, as the inspector already does. Its current `path.open('rb')` can block indefinitely opening a FIFO, before `fstat()` gets a chance to reject the nonregular type. This affects required stage/queue files and catalogs directly. Such reads occur outside the subprocess timeouts; the wrapper also has no overall planning deadline. This is a source-proven malformed-state boundedness gap, not evidence that the current inspected target contains a FIFO.

`provenance()` also applies its 512-file limit after traversal and all file hashing. Move the count check into bounded enumeration before reads to make that stated bound effective. Recursive enumeration itself has no entry/depth budget. Normal retained configuration is small; this does not establish corruption or a current runtime failure.
