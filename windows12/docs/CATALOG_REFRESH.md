# Bounded native APT catalog regeneration

Source implementation only, 2026-11-06. No VM, target package operation, project-module execution, Git action or host test suite was run for this helper. Runtime integration and validation remain pending.

`build/refresh-package-catalogs.py --nonce <32hex>` runs only as root in the contained marked guest, from `/root/windows12-build`, during a fresh boot under1800seconds. It is a separate update-only cache operation following another retained Packages/signature mismatch. It does not invoke live-build, preparation, installers, target binaries, dpkg package actions or install/upgrade commands. No `.build` completion invalidation is needed: the package payload/status and completed stages must remain unchanged.

Before any mutation, the helper requires the approved144-package status SHA256 `cf0bdc5bd7e2c0332cb2906f099c044077321f6583fc4eb45eac7d452b2c91e8`, stored MD5 metadata144 files/450161bytes/SHA256 `1dfcd7999383a91e54e9cec6729910adcabde8b22f102c81294a239bcfc8bb76`, exact nineteen flags from inspection62707, and five approved saved-config hashes. It scans processes/mounts, hashes all retained dpkg/config/flag/APT-config/archive/bootstrap-cache files and captures the queue/extended-states/lock. Only reviewed build-hook links may occur in config provenance; their literal targets and installed bytes are recorded without execution. Other aliases/special files fail. Trees are bounded by8192 entries/depth16 and512MiB; individual regular files by256MiB, checksum metadata by16MiB. No host or target mount is created.

Target source files must be traditional `.list` syntax with exactly the reviewed Debian trixie/trixie-updates/security endpoints and main/contrib/non-free/non-free-firmware, plus one exact `file:/packages ./` local source. Unknown hosts/suites/components/options, ambiguous local sources and Deb822 require review and fail closed. The target source/config files are never edited. Actual retained local catalog filenames are `_packages_._Packages` and `_packages_._Release`.

The whole old lists directory is renamed on its existing image filesystem into a unique sibling `windows12-catalog-quarantine-<nonce>/lists`. Existing target pkgcache.bin/srcpkgcache.bin are also renamed there with exact hashes and metadata preserved; combined reproducible cache bytes are capped at512MiB. Rename/report/directory fsync checkpoints preserve evidence. The helper creates a fresh target lists directory. It never deletes or restores the old directory, including on failure.

The trusted builder's absolute `/usr/bin/apt-get update` is the sole package-manager command. Private source/config/output files live in `/project-output/catalog-refresh-<nonce>`. `APT_CONFIG` explicitly replaces config parts/main/sourceparts/trustparts with private empty paths, clears update/install/dpkg hooks, directs lists/status explicitly into the retained target, and places cache/log/extended-state outputs in the private workspace. It does not load target APT hooks or resolver configuration. It uses fresh HTTPS versions of the same three official remote sources, each with `Signed-By=/usr/share/keyrings/debian-archive-keyring.pgp`; no file URI is fetched because `/packages` is absent on a fresh unmounted boot. Builder proxy environment and optional `SSL_CERT_FILE` CA are passed through explicit APT acquisition settings. TLS peer/hostname and repository authentication remain enabled; insecure/downgrade/unauthenticated repositories are forbidden.

`Acquire::Languages=none`, uncompressed package indexes, error-mode any, short acquisition timeouts/retries, a600second process-group timeout, bounded file-backed output and CPU/file-size limits constrain the update. The environment is reconstructed so unrelated APT_CONFIG/options cannot inject hooks. Root sandbox selection keeps acquisition within the already contained guest and private directories.

Only after native update returns0 does the helper copy the exact two original local Packages/Release byte streams back from quarantine into the new lists directory. Their originals remain preserved. It never synthesizes local package metadata or mounts `/packages`. Then it compares retained provenance, target sources, old quarantined lists and binary-cache hashes against the initial inventory and confirms boot/quiescence again. Target binary caches must remain absent. All completed flags, archives, dpkg database, target config/trust/sources, queue and retained bootstrap cache must match.

The atomic `/project-output/package-catalog-refresh.json` records nonce, native command/result/output hashes, full before/after provenance, old/new list hashes, local catalog restoration, source/keyring/builder-tool evidence and quarantine records. `refresh_completed=true` requires update0 plus preservation checks; it means native APT update completed, not an independent full signature/catalog audit. The next package-plan exporter must still SQV-verify every signed release and match each retained Packages byte stream to its signed digest. On any failure, partial lists, logs and old quarantine remain; no rollback/cleanup is attempted, and bounded failure snapshots are recorded when readable.

Validation here is limited to AST parsing and source review against the existing inspection JSON. Fresh contained execution, successful remote update, retained-state equality and independent exporter audit are pending.
